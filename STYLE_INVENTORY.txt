KIPPY'S TAROT — STYLE INVENTORY
Prepared: November 4, 2026
Purpose: Week 1 / Day 2 preparation for the styled-components migration.

SCOPE AND HOW TO USE THIS FILE
=============================
Source audit of all nine frontend/src/components/*.jsx files, index.css,
App.css, App.jsx, main.jsx, and frontend/index.html. No application styles
were changed. This is a source inventory, not a browser/computed-style audit.
Source locations below are relative to the project root and reflect this snapshot.

Sections 1–9 summarize shared patterns, important exceptions, and decisions.
Appendix A lists repeated declarations with their component locations.
Appendix B preserves every styled-component definition, including nested states,
media queries, interpolations, comments, duplicates, and empty definitions.
Appendix C records global CSS, font loading, inline styles, and icon sizing.
Comments in the appendix are historical source, not active design requirements.
Suggested names below are proposals; no theme tokens currently exist in source.

2. TYPOGRAPHY
=============
Primary font: "Pixelify Sans", sans-serif.
  Root: weight 400, style normal; button font-family inherits.
  Explicitly repeated for Login/SignUp/Profile/Reading input placeholders and
  Journal textarea text/placeholder. Input text itself has no explicit font-family.

  weights 100–900 (normal/italic). No Poppins font-family usage found in src.
Weights:
  400: root.
  420: Home/Reading text panels, History text/list cards, Profile text panel.
  500: global links/buttons, Journal title, TarotCard meaning label.

  1em: global and several component buttons.
  1.1em: Header navigation and logout.
  14px: TarotCard meaning label.
  16px: Journal textarea and back-button text.
  30px: Header title and Journal title.
  40px: Header menu icon container.

Rendering: font-synthesis none; text-rendering optimizeLegibility;
  -webkit-font-smoothing antialiased; -moz-osx-font-smoothing grayscale.
White text outline, shared by Journal.Title and TarotCard.CardData:
  -1px -1px 0 #ffffffff, 1px -1px 0 #ffffffff,
  -1px 1px 0 #ffffffff, 1px 1px 0 #ffffffff.

7. POSITIONING, STATES, AND ANIMATION
=====================================
Header.HeaderBlock: absolute top/left/right 0, height 50px,
  padding 0 20px, z-index 100.
Header.Overlay: fixed on all four edges, z-index 150,
  display block/none from $isOpen.
Header.Menu: fixed top 0, left 0 when open / -500px when closed,
  width 200px, height 100%, padding 80px 20px 20px,
  z-index 200, transition left 0.3s ease.
Header.LoginPlacement: relative, margin-top 300px.
Other stacking: TarotCard.CardData z-index 2; History.BinIcon z-index 10.
Native modal dialogs use browser modal behavior; do not replace it with an
ordinary positioned div solely to reproduce the visual surface.

Transitions:
  Global buttons: border-color 0.25s.
  Header navigation/logout: background 0.2s (hover changes text color).
  History link/trash: color 0.2s ease.
  History wrapper: all 0.25s ease, hover scale(1.02).
  History saved entry also scales to 1.02 on parent hover; both scales compound.
  Profile delete: background 0.2s ease, color 0.2s ease.
  Tarot FrontCard: transform 1s ease; hovered rule changes to all 1s ease,
    scale(1.15), decorative gradient/glow.
  Tarot flip: ReactCardFlip with horizontal direction and isFlipped state;
    animation internals come from the library, not the local CSS definitions.
  Reversed card image: inline rotate(180deg) or none.

History parent/child states:
  Hovering ReadingWrapper colors link/trash purple and adds entry glow/scale.
  Hovering the trash icon itself overrides purple with danger red.
Password controls:
  Relative wrapper and absolute eye icon, right 30px, pointer cursor,
  black at rest and primary purple on hover.
  SignUp: top 55%, translateY(-50%). Login differs; see quirks below.

8. GLOBAL DEPENDENCIES AND EXISTING QUIRKS
=========================================
- main.jsx imports index.css. App.css is empty. App's className="App" has no
  authored matching CSS rule in the inspected source.
- No universal box-sizing reset is authored. Only Journal textarea and tarot
  meaning label explicitly use border-box. Check computed sizing before adding
  a reset: fixed widths/heights can include different padding/border totals.
- Root color-scheme is light dark. Native inputs/dialogs and inherited colors
  may differ by OS/browser preference.
- Global WebKit scrollbar rule hides scrollbars. History explicitly restores
  its list scrollbar (8px width, 50px height, rounded thumb). Other engines can
  behave differently; no equivalent scrollbar-width rule is authored.
- Many controls suppress outlines and use border changes for focus. Global
  button:focus-visible also exists; verify actual keyboard focus rendering.
- Global paragraph margins, native form-control defaults, dialog defaults,
  and image display behavior are not fully reset in source.
- frontend/index.html has no viewport meta tag. Mobile rendering needs a
  browser baseline; adding one is a separate behavior change.
- Login.EyeIcon has misspelled transform: trasnlateY(-50%) and top: 35%.
  That transform is invalid. SignUp uses translateY(-50%) and top: 55%.
  Flag this for a deliberate fix rather than silently treating them as identical.
- TarotCard.FrontInner defines conditional rotation but is not rendered;
  actual reversal is the inline FrontImage transform.
- Login.LoginText is defined but not rendered. Profile.Content and
  Reading.CenteredPrompts are empty styled wrappers (the latter is rendered).
- TarotCard.CardData declares inline-block then flex (flex wins), and repeats
  text-align. Several blocks declare white/fallback colors before overriding.
- Some align-items/justify-content declarations are on elements without a
  flex/grid display; do not assume those declarations currently center content.
- Fixed 400/550/600px widths, wide card rows, and dialog padding need checks on
  small screens. Preserve the baseline before scheduling responsive fixes.
- Journal.BackButtonText hides at <=888px, including the text inside its
  unauthenticated login button; check that state when reviewing mobile behavior.
- No authored disabled-state rules, reduced-motion media rules, or keyframes
  were found in the reviewed app source. Library behavior is outside this audit.

9. PROPOSED MIGRATION CONVENTIONS (NOT IMPLEMENTED)
==================================================
- Give repeated semantic colors names: accent, navigation-accent, danger,
  danger-border, panel, control-surface, card-surface, drawer, page-pink/page-blue.
- Give shared shadow and font named tokens; keep complex glow/text-outline
  effects in readable CSS if that makes them easier to maintain.
- Build shared button/input/panel/dialog components only after accounting for
  the variations above. Keep existing HTML semantics and event behavior.
- Preserve exact dimensions, alpha values, em units, and breakpoint boundaries
  in the first pass. Layout redesign and defect fixes should be explicit changes.
- Use complete conditional class strings for open/closed and reversed states.
- Retain parent-driven hover behavior and the nested trash-hover override.
- Check all global style dependencies before changing reset/cascade behavior.
